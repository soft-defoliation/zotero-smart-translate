# SmartTranslate 真机测试指南

> **1.2.0 起请优先使用 [acceptance-1.2.0.md](acceptance-1.2.0.md)** (新功能验收 + 历史修复复测); 本指南保留作旧版构建的详细排查参考。

> 适用版本：xpi ≥ 47073 字节（2026-09-11 构建）｜Zotero 10.0.1
> 全程约 15–20 分钟。按顺序做，每步给"预期"和"失败怎么办"。

---

## 第 0 步：准备一篇能打开的 PDF（最重要）

你的库附件多为链接文件且基目录失效，先自测：
双击任意一篇文献的 PDF —— **若能正常打开**，跳过本步；**若提示"找不到文件"**，三选一：

- **最快**：拖一个 PDF 文件从资源管理器进 Zotero 库（生成新条目），这个附件一定可用；
- 或：修链接基目录 —— 编辑 → 设置 → 高级 → 文件和文件夹 → "链接附件的根目录" 改成你论文的实际路径；
- 或：下载一篇开放获取论文的 PDF 拖进库（推荐用你领域的，如 arXiv 上的铁电/高压论文）。

> 后面所有测试都用这篇"能打开"的 PDF。

## 第 1 步：安装新版插件

1. 工具 → 插件 → 右上角齿轮 → **从文件安装插件**；
2. 选这个文件：
   `D:\Hermes\projects\zotero-smart-translate\.scaffold\build\smart-translate-for-zotero.xpi`
3. 装完看插件卡片：**Last Updated 应变成今天**（版本号一直是 0.1.0，认日期）；
4. 正常情况**不用重启**（新版支持中途启用）；如果下面第 2 步侧栏不出现，**重启一次 Zotero** 再试——这一步本身就在验证"免重启升级"修复。

## 第 2 步：检查设置

编辑 → 设置 → SmartTranslate，逐项核对：

| 项 | 应为 |
|---|---|
| API Key | 密码框有内容（没填就粘贴你的智谱 Key） |
| 接口地址 | `https://open.bigmodel.cn/api/paas/v4/chat/completions` |
| 模型 | `glm-4.6`（推荐；之前若是 glm-4-flash 请改掉） |
| 目标语言 | 简体中文 |
| 翻译行为-自动翻译 | 勾选 |
| 翻译行为-跳过中文 | 勾选 |
| 翻译行为-自动切换备用引擎 | 勾选 |
| 写回模式 | 先选**关闭**（第 6 步单独测） |

改完点一下别处（失去焦点即保存），**关掉设置窗口再重新打开**，确认刚才的改动还在（持久化验证）。

---

## 第 3 步：侧栏

1. 双击打开第 0 步的 PDF；
2. 看右侧条目面板（如果没有，点工具栏右上的"开/合条目窗格"按钮）；
3. **预期**：出现 "SmartTranslate" 侧栏，含引擎下拉 + 翻译按钮、原文框、译文框、底部复制按钮。

**失败对照**
- 侧栏完全不出现 → 重启 Zotero 再看；仍没有 → 截图（含"编辑→设置→高级"右栏也行）；
- 侧栏标题空白/显示怪字符 → 截图给我（l10n 已知风险点）。

## 第 4 步：划词翻译（核心）

在 PDF 里划选一段英文，逐项看：

| 观察点 | 预期 |
|---|---|
| 弹窗 | 出现译文框，约 0.7s 开始逐字出中文，1–2s 出完 |
| 侧栏 | **同步**显示同一段翻译 |
| 术语 | 含 ferroelectric 的词句，必须译成"铁电"（术语锁定生效标志） |
| 复制 | 在译文里拖选 Ctrl+C；双击译文=整段复制（出现"已复制"小字） |
| 调尺寸 | 拖译文框右下角把手，下次划词尺寸被记住 |
| 再划一段**中文** | 弹窗显示"检测到中文，已跳过翻译" |
| **同一句英文**再划一次 | 瞬间出结果（缓存命中，无等待感） |

**失败对照**
- 显示"翻译失败: …401" → Key 问题（回第 2 步）；
- 显示"翻译失败: …限流/429" → 等 10 秒重试（免费档限流正常）；
- 译文仍是宋体/衬线 → 回设置"弹窗外观"选字体（微软雅黑/思源宋体）再试。

## 第 5 步：拼接模式

1. 划第一段 → 弹窗点 **＋拼接**（预期：不翻译，出现"已拼接 1 段"）；
2. 划第二段 → 弹窗顶部应显示上次内容 → 再点 **＋拼接**（"已拼接 2 段"）；
3. 点 **翻译拼接** → 预期：两段合并成一次翻译；
4. 另测 **清空**：＋拼接后点清空，缓冲归零回到普通模式。

> 失败的典型表现：点"翻译拼接"没反应或报"另一处翻译进行中"——后者说明你正好有别的翻译在跑，等它完再点（我们刚修过这个场景，缓冲不会再丢）。

## 第 6 步：写回收集

1. 设置 → SmartTranslate → 写回模式 → **收集双语对照到子笔记**；
2. 回 PDF 划词翻译一次；
3. 到库视图找到该文献条目 → 展开它 → **预期**：出现子笔记 **"SmartTranslate 收集"**，内含原文 + 引用块译文 + 时间；
4. 再划词一次 → 预期**追加**第二条（不会新建第二个笔记）；
5. 测完把写回模式改回**关闭**。

## 第 7 步：阅读助手（花 API 费用，一篇约几分到两毛）

1. 库视图 → 右键第 0 步的条目 → **"SmartTranslate: 阅读助手（摘要/创新点/方法）"**；
2. **预期**：进度窗出现，逐块推进（"翻译中 3/12 (25%)"之类），几十秒–几分钟后显示 **"已写入子笔记 📝"**；
3. 到条目下看新子笔记：应有三节——📑 全文摘要 / 💡 创新点（列表）/ 🔬 方法结构化（组成/合成/表征/DFT/加载条件）；
4. 抽查一条创新点，看是否真的来自这篇论文、没有编造。

**失败对照**
- "无可用全文" → 这篇的 PDF 不可访问（回第 0 步换一篇）；
- 中途报限流 → 它是逐块串行翻译，被限流会在进度窗留 ⚠ 行，重跑一次即可（已翻的块有缓存不重复花钱）。

## 第 8 步：批量导出

1. 选 2–3 篇**有可用 PDF**的条目（Ctrl 多选）→ 右键 → **"SmartTranslate: 批量翻译导出（双语 Markdown）"**；
2. **预期**：弹文件夹选择框 → 选一个空文件夹 → 进度窗逐条目推进 → 结束显示 "导出完成: 成功 N / 失败 M · 文件夹: …"；
3. 打开该文件夹：应有 N 个 `.md`，每个含标题 + 原文 + `> 译文` 对照。

## 第 9 步：故障转移（可选，5 分钟）

人工制造故障来验证：

1. 设置里把 **Engine 1（当前引擎）的 API Key 故意改错一位**；
2. 把正确的 Key 填到 **Engine 2**；
3. 回 PDF 划词 → **预期**：照样出译文，侧栏状态行显示 **"已完成 · Engine 2（故障转移）"**；
4. 连续划 3 次后回设置看：**当前引擎已自动变成 Engine 2**（粘性切换）；
5. 测完把 Key 改回、引擎切回 Engine 1。
